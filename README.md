# VMware-Disk-Spoofing-Bypass

A Windows kernel-mode filter driver (`AceSpyDrv.sys`) that spoofs disk
identifiers reported to user-mode applications. Its primary purpose is to
hide the tell-tale serial/model/firmware strings of virtual disks (VMware,
VirtualBox, Hyper-V, QEMU, …) so that anti-cheat / fingerprinting tools
that read raw disk identify data cannot detect the virtual machine.

The driver is **PatchGuard-safe**: it does **not** use inline hooks or
`MajorFunction` hijacking. Instead it attaches to the disk device stack via
`IoAttachDeviceToDeviceStack` and only patches the IRP completion in its own
stack location.

## Features

Intercepts every common disk-identify path and rewrites the serial number,
model name, firmware revision, WWN / EUI64 / NGUID and selected SMART
attributes before the response is returned to user mode.

### Buffered IOCTLs (system buffer — safe at any IRQL)

| IOCTL | Code | Used by |
|-------|------|---------|
| `SMART_RCV_DRIVE_DATA`              | `0x7C088`   | CrystalDiskInfo |
| `IOCTL_ATA_PASS_THROUGH`            | `0x4D02C`   | ATA IDENTIFY `0xEC` |
| `IOCTL_SCSI_PASS_THROUGH`           | `0x4D004`   | SCSI INQUIRY `0x12` |
| `IOCTL_SCSI_PASS_THROUGH_EX`        | `0x4D018`   |  |
| `IOCTL_SCSI_GET_INQUIRY_DATA`       | `0x41018`   | Legacy bus scan |
| `IOCTL_STORAGE_QUERY_PROPERTY`      | `0x2D1400`  | `StorageDeviceProperty` + `StorageDeviceIdProperty` (NVMe ctrl identify) |
| `IOCTL_STORAGE_PROTOCOL_COMMAND`    | `0x2D14F0`  | NVMe Admin Identify |

### Direct IOCTLs (DataBuffer is user VA — MDL-mapped before patching)

| IOCTL | Code |
|-------|------|
| `IOCTL_ATA_PASS_THROUGH_DIRECT`        | `0x4D028` |
| `IOCTL_ATA_PASS_THROUGH_DIRECT_EX`     | `0x4D030` |
| `IOCTL_SCSI_PASS_THROUGH_DIRECT`       | `0x4D014` |
| `IOCTL_SCSI_PASS_THROUGH_DIRECT_EX`    | `0x4D01C` |

### NVMe vendor pass-through

| IOCTL | Code |
|-------|------|
| `NVME_PASS_THROUGH_SRB_IO_CODE` | `0xE0000800` |
| Intel NVMe pass-through         | `0xF000A02`  |

### Spoofed fields

* **ATA IDENTIFY** — serial (words 10-19), model (27-46), firmware (23-26),
  WWN (84-87 + 108-111)
* **SCSI INQUIRY** — vendor, product, revision, unit serial number page `0x80`
* **NVMe Identify Controller** — serial, model, firmware, EUI64 / NGUID
* **SMART attributes** — zeroes ID 9 (Power-On Hours) and ID 12 (Power Cycle
  Count). ID 194 (Temperature) is preserved because it is not unique.

## Prerequisites

* **Visual Studio 2022** (the `vcvars64.bat` of VS 2017/2019/2022 is auto-detected)
* **Windows Driver Kit (WDK)** 10.0.28000.0 or 10.0.26100.0
* Windows 10/11 x64 target

## Building

```bat
build.bat
```

The script will:

1. Locate `vcvars64.bat` and the WDK include/lib directories.
2. Compile `AceSpyDrv.cpp` with `cl /kernel /O2`.
3. Link `AceSpyDrv.sys` against `ntoskrnl.lib`, `hal.lib`,
   `BufferOverflowFastFailK.lib`, `wmilib.lib`.
4. Generate a self-signed code-signing certificate (`AceSpyTestCert.pfx`,
   password `AceSpy123`) the first time it runs, and sign the driver with
   `signtool.exe`.

## Loading the driver

`AceSpyDrv.sys` is **not** installed as a service. It is mapped directly into
the kernel with **KDU** (`kdu.exe`), which avoids PatchGuard detection and
does not require test-signing mode to be enabled.

```bat
kdu.exe -map AceSpyDrv.sys
```

To unload, reboot the machine (the driver is not persistent).

> If you prefer the standard service-based approach, enable test-signing
> mode (`bcdedit /set testsigning on`), reboot, then create and start a
> service pointing at `AceSpyDrv.sys`.

## How it works

1. On `DriverEntry` the driver walks the `\Driver` directory object with
   `ZwQueryDirectoryObject` and locates every storage-related driver
   (`disk`, `partmgr`, `storahci`, `stornvme`, `pciide`, …).
2. For each device object owned by those drivers it calls
   `IoAttachDeviceToDeviceStack` and stores the filter extension.
3. The filter's `IRP_MJ_DEVICE_CONTROL` dispatch routine inspects the IOCTL
   code, lets the lower driver complete the request, and on completion
   rewrites the identifying fields in the response buffer (handling both
   buffered and direct I/O, including MDL-mapping user-mode `DataBuffer`).
4. Original serials are cached the first time they are seen so the spoofed
   value is stable across queries.

Because the driver only patches the completion of IRPs that pass through its
own stack location (and never touches the lower driver's code or
`MajorFunction` table), it is invisible to PatchGuard.

## Configuration

The spoofed serial/model strings are generated at runtime inside
`AceSpyDrv.cpp`. Edit the relevant generator helpers and rebuild to
customise the output format.
